## Базовые вопросы и короткие ответы

**Что такое frontend и backend?** Frontend показывает интерфейс и принимает действия пользователя. Backend хранит данные, проверяет запросы и выполняет операции над ними. Общаются по HTTP через API.

**Что такое API-контракт?** Договор о маршрутах, методах, параметрах, JSON и кодах ответов. Например, POST /enrollments принимает courseId и studentName, а возвращает их вместе с id.

**Что такое origin?** Сочетание протокола, host и порта. localhost:3000 и localhost:8000 — разные origins. localhost и 127.0.0.1 тоже разные hosts. Путь страницы в origin не входит.

**Что такое CORS и зачем он здесь?** Механизм разрешения браузеру читать ответы другого origin. Наш backend явно разрешает http://localhost:3000. Заголовок Origin браузер добавляет сам.

**CORS защищает API от запросов?** Нет. Простой запрос может выполниться и изменить данные даже при блокировке чтения ответа. curl и другие серверы не обязаны соблюдать браузерный CORS. Для защиты нужны отдельные механизмы авторизации.

**Почему каталог работает без CORS, а фильтр нет?** Каталог — Server Component: запрос отправляет процесс Next.js. Фильтр — Client Component: запрос отправляет браузер, который проверяет CORS.

**Что делает use client?** Обозначает границу клиентских компонентов: доступны состояние и обработчики событий. Поэтому фильтр, кнопка, форма и error.tsx — клиентские.

**Зачем SWR?** Загружает и кэширует данные в браузере, повторно проверяет их актуальность, предоставляет data, error, isLoading. При смене checkbox меняется ключ URL и выполняется запрос с новым фильтром.

**Почему isElective, но ?is_elective=true?** Pydantic-алиасы меняют поля JSON-моделей. Query-параметр определён аргументом функции list_courses и остаётся snake_case.

**Зачем validate_by_name?** Чтобы данные в data.py принимались по Python-имени is_elective. Без него поле с алиасом isElective может проигнорировать is_elective=True и оставить False по умолчанию.

**Что делает res.ok?** Проверяет диапазон статусов 200–299. fetch сам по себе не бросает исключение на HTTP 404 или 500, поэтому ошибки нужно проверять явно.

**Почему 404 возвращает undefined?** Отсутствие курса — ожидаемый результат. Страница вызывает notFound(), чтобы показать not-found.tsx. Остальные ошибки бросаются в error.tsx.

**Зачем no-store?** Не использовать постоянный кэш запроса: на новом открытии страницы получать актуальные лайки и курсы. Это серверный параметр fetch; кэш SWR в браузере — отдельный механизм.

**Почему удалён generateStaticParams?** Он вызывал getCourses во время сборки, делая её зависимой от запущенного API. Курсы теперь меняются на backend без пересборки frontend, поэтому страницы рендерятся по запросу.

**Что такое preflight?** Предварительный OPTIONS, которым браузер проверяет разрешение на метод и заголовки будущего запроса. У него есть Origin, Access-Control-Request-Method и Access-Control-Request-Headers.

**Почему у лайка нет OPTIONS, хотя он POST?** POST без тела и нестандартных заголовков удовлетворяет условиям простого запроса. У формы Content-Type application/json не входит в safelisted Content-Type, поэтому необходим preflight. Разрешение может кэшироваться.

**Что означают 200, 201, 404, 422, 500?** 200 — успешно; 201 — создана запись; 404 — курс не найден; 422 — данные не соответствуют модели; 500 — необработанная ошибка сервера.

**Где проверяется имя?** В EnrollmentIn: Field(min_length=2). FastAPI автоматически возвращает 422 до вызова обработчика. Форма читает detail[0].msg. Клиентский minLength намеренно не добавлен, чтобы продемонстрировать серверную валидацию.

**Почему два типа EnrollmentIn и Enrollment?** Клиент отправляет только courseId и studentName; сервер сам назначает id. Входная модель не доверяет клиенту назначение идентификатора.

**Куда сохраняются лайки и записи?** В память процесса Python: Course.likes и список ENROLLMENTS. Обновление страницы их не стирает, перезапуск API — стирает. Базы данных в этой работе ещё нет.

**API_URL и NEXT_PUBLIC_API_URL — в чём отличие?** Первая доступна серверному коду, вторая публикуется в браузерном bundle. Префикс PUBLIC нельзя использовать для секретов. После изменения env нужен перезапуск dev-сервера.

**Зачем import type?** TypeScript берёт только описание данных и удаляет импорт из JavaScript. Серверный код lib/courses.ts не попадает в клиентский компонент через этот импорт.

**retry и reset — в чём разница?** В установленном Next.js 16.3.5 retry повторно запрашивает серверные данные и перерисовывает сегмент. reset только сбрасывает состояние error boundary, поэтому здесь используется retry.

**В Console CORS error: сразу менять allow_origins?** Сначала проверить URL, статус и terminal backend. При 500 ответ может не получить CORS-заголовки, а настоящая причина — Python-ошибка, например KeyError. Если серверный каталог тоже падает, это сильный признак ошибки backend, а не CORS.
